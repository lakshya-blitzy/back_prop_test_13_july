{#- pretty/_stats_table.html - the grouped twelve-column statistics table of the generated report tree, shared by four of its six pages. Macro-only: it renders no page and is never a render target, and consumers import it - {% import 'pretty/_stats_table.html' as stats %} - because no macro reads an ambient template variable; every value arrives as an argument. THE MACROS, each one's parameters and defaults documented at the macro: stats_table(rows, first_column_label, totals=none, sortable=true) stats_header(first_column_label) stats_row(row) stats_footer(totals, row_count=none) An overview takes the sortable form, whose id is what _layout.html's tablesorter initialisation binds to, and supplies totals for its footer; a detail page holds one row, so it passes sortable=false and no totals. THE RENDER CONTEXT. A ROW is one mapping per feature or tag, or a detail page's single subject: name; optional href, a plain relative filename local_page_href must accept or the name renders unlinked; the six step and three scenario counts in the column order below; duration_ns as RAW NANOSECONDS, never a formatted string, since the sort attribute carries it verbatim and _macros.html owns the human form; and status in any case, folded by partials/status_badge.html. THE TOTALS mapping adds run-level sums of those nine counts, duration_ns, the features count that is the DENOMINATOR of the last percentage and the optional features_passed that is its numerator. Every key of both is reached defensively, so an absent value renders 0, an empty cell, plain text, Unknown or no footer instead of raising. THE COLUMN SET IS FIXED AT TWELVE, grouped 1 + 6 + 3 + 2, Duration and Status sitting under the Features heading as the generator groups them. The grouping row's dont-sort class is LOAD-BEARING: the tablesorter initialisation selects '> thead tr:not(.dont-sort) th', so that class alone keeps the colspan row out of the sortable header set. CLASS VOCABULARY. The generator's bare classes are kept in full, and the port's own are additive: tqa-link on the row-key anchor, tqa-duration on both duration cells through the duration macros' extra_classes parameter, data-report-status on the body row and the status cell, and tqa-table on the table. tqa-table is REQUIRED rather than decorative: main.css scopes the required status palette to .tqa-table th. and td., at a specificity that outranks cucumber.css's bare status classes, and without it the header row and every skipped cell render in the vendored light blue. main.css's rules for data-report-status set custom properties only, so that hook paints nothing by itself. STATE: none of report.js's three runtime classes (report-is-collapsed, report-is-filtered-out, report-lightbox-is-open), which that script alone writes and main.css alone reads, and no mutable ARIA mirror either - the table's role and accessible name are static semantics. data-report-status is classification, and no filtering hook is emitted, because these rows are not independently hideable. THE TABLE SITS IN ITS OWN SCROLL REGION - div.tqa-table-wrap with tabindex="0", role="region" and an accessible name - owned by the macro rather than by its four callers, since a caller that omitted it would reintroduce the overflow of twelve columns on one page. main.css confines that overflow to the wrapper and drops the constraint in print. -#} {#- Formatting, borrowed from its single owner. Every cell that carries a count, a duration, a percentage or a status label is built by a macro there, so this file decides WHICH cells exist and in what order, and never how a value is rendered. -#} {%- import 'pretty/_macros.html' as fmt -%} {#- Status normalisation, imported from its own single owner rather than through the alias above: a name that file imports is not re-exported through its namespace. -#} {%- from 'partials/status_badge.html' import status_token -%} {#- --------------------------------------------------------------------------- The grouped two-row header, identical on all four pages but for the first cell of the second row. first_column_label REQUIRED in practice: 'Feature' or 'Tag'. Absent, none or blank renders an empty header cell rather than raising, which keeps a page that forgot it readable instead of unbuilt. --------------------------------------------------------------------------- -#} {%- macro stats_header(first_column_label) -%} {%- set key_label = first_column_label|default('', true)|string|trim -%} {#- Every macro in this file opens its markup with no leading indentation of its own and closes at the nesting level of its own element, so the caller places it: stats_table indents each call site once and the emitted tree comes out nested and readable rather than flush left. -#} {#- The grouping row. Its class pair is what excludes these three cells from the sortable header set; see the vocabulary note above. #} {#- The empty corner cell of the grouping row. It heads the row-key column, which the body rows repeat as a th scope="row", so it takes a column scope like every other header cell here rather than being the one cell a reader's table model cannot place. #} Steps Scenarios Features {#- The twelve column headers, in the one order the contract fixes. The five status classes here are the same words the body cells carry, so a reader matches a column to a colour without reading the header. #} {{ key_label }} Passed Failed Skipped Pending Undefined Total Passed Failed Total Duration Status {%- endmacro -%} {#- --------------------------------------------------------------------------- One body row: twelve cells, in the header's order. row REQUIRED. The mapping described in the render context above. A missing key, a null value and a row that is not a mapping at all all render - as a zero, an empty cell or an unknown status - because one malformed row must not cost the reader the other rows. Nine of the twelve cells are built by pretty/_macros.html, which owns the two rules they follow: a count cell carries its status class ONLY when the count is non-zero, so a zero is a bare cell, and a Total cell always carries its class, including for zero. Neither rule is restated here. --------------------------------------------------------------------------- -#} {%- macro stats_row(row) -%} {#- The whole row is reached through one guarded name, so every cell below reads the same object and a non-mapping row degrades once rather than twelve times. -#} {%- set data = row|default({}, true) -%} {#- The presentation status, folded exactly once and used twice: as the cell's generator class and as the port's status hook. Deriving it twice is how a cell's colour and its hook come to disagree. -#} {%- set token = status_token(data.status) -%} {%- set label = data.name|default('', true)|string|trim -%} {#- The destination, through the writer's own allowlist. A row's href is model-owned in the general case - a caller may hand this macro a row it assembled from the result document - and a destination that is not a page this tree emits is dropped here rather than rendered as an active link. local_page_href is a global of the environment app/reporting/pretty_reports.py builds, which is the one place that renders this folder; it answers '' for anything it does not recognise, and the branch below then renders the row key as plain text. -#} {%- set link = local_page_href(data.href|default('', true)|string|trim) -%} {#- A blank name would leave an anchor with no accessible name at all, so the link target's own text stands in - a value the model already carries, never a label invented for a system this port deliberately does not rename. With neither a name nor a target the cell is empty, which is what the generator emits for a nameless subject. -#} {%- set key_text = label if label else link -%} {#- The row key, as the row's own header cell: it identifies the eleven cells that follow, so it is a th with a row scope and not a data cell, and it keeps the tagname class. An anchor where the caller supplied a destination, plain text otherwise. THE THREE INLINE DECLARATIONS ARE A SPECIFICITY CONSTRAINT, which is the one thing about this cell that is not obvious. cucumber.css centres the whole table - `table.stats-table th, table.stats-table td { text-align: center }` at (0,1,2) - and exempts this column only through `table.stats-table td.tagname { text-align: left }`, a rule scoped to the td ELEMENT, so nothing a th can carry restores the left alignment: Bootstrap's .text-left and the port's own .tqa-table rules are both weaker. text-align is therefore declared here, on the one cell no available selector reaches. THE OTHER TWO GUARD THE SAME SEAM. A caller may add the port's tqa-table class to this shared table - overview_steps.html carries it on its own table - and `.tqa-table th` sets white-space: nowrap and the header background colour, both right for a header ROW and wrong for a row header inside the body: the nowrap alone widens this key column past its container, and the background tints a body column the contract leaves white. Declaring them here keeps this macro's rendering identical whether or not that class is present. font-weight is deliberately not among them: a row header reading bolder than its data is correct. #} {% if link %}{{ key_text }}{% else %}{{ key_text }}{% endif %} {{ fmt.count_cell(data.steps_passed, 'passed') }} {{ fmt.count_cell(data.steps_failed, 'failed') }} {{ fmt.count_cell(data.steps_skipped, 'skipped') }} {{ fmt.count_cell(data.steps_pending, 'pending') }} {{ fmt.count_cell(data.steps_undefined, 'undefined') }} {{ fmt.total_cell(data.steps_total) }} {{ fmt.count_cell(data.scenarios_passed, 'passed') }} {{ fmt.count_cell(data.scenarios_failed, 'failed') }} {{ fmt.total_cell(data.scenarios_total) }} {#- The sortable duration cell. Its sort attribute carries the raw nanosecond count, which is the only reason 1:40.186 sorts above 24.654 instead of below it lexically. #} {{ fmt.duration_cell(data.duration_ns, extra_classes='tqa-duration') }} {#- The status: the generator's background through the class, the word itself through the label, and the port's hook alongside both. #} {{ fmt.status_label(data.status) }} {%- endmacro -%} {#- --------------------------------------------------------------------------- The footer, on the two overview pages only. totals REQUIRED. The totals mapping described above. row_count OPTIONAL. The number of rows the table rendered, which is what the sum row's last cell reports. stats_table always supplies it, reproducing the generator's $items.size() exactly - the number of rows in THIS table, so tags on the tags page. A caller invoking this macro on its own may omit it, and the totals mapping's features key is then used instead. Two rows, and the shape of the second is measured rather than derived: it leaves the cells under both Total columns and under Duration EMPTY. A percentage of a total against itself is always 100% and says nothing, and a percentage of a duration is meaningless, so the generator prints neither. They are not gaps to fill. --------------------------------------------------------------------------- -#} {%- macro stats_footer(totals, row_count=none) -%} {%- set data = totals|default({}, true) -%} {#- The sum row's last cell: the rendered row count where the caller gave one - a genuine zero included, which is why this tests definedness rather than truthiness - and the run's feature count otherwise. -#} {%- set subject_count = row_count if row_count is not none else data.features -%} {#- The class on the element, not on its cells: it is what tints the whole block. The nine count cells below are deliberately unclassed. -#} {{ fmt.count_cell(data.steps_passed) }} {{ fmt.count_cell(data.steps_failed) }} {{ fmt.count_cell(data.steps_skipped) }} {{ fmt.count_cell(data.steps_pending) }} {{ fmt.count_cell(data.steps_undefined) }} {{ fmt.count_cell(data.steps_total) }} {{ fmt.count_cell(data.scenarios_passed) }} {{ fmt.count_cell(data.scenarios_failed) }} {{ fmt.count_cell(data.scenarios_total) }} {#- The total duration, through the macro variant that has no sort attribute in it at all: a footer row is never sorted, so emitting one here is not a mistake this file can make. #} {{ fmt.duration_total_cell(data.duration_ns, extra_classes='tqa-duration') }} {{ fmt.count_cell(subject_count) }} {{ fmt.percent_text(data.steps_passed, data.steps_total) }} {{ fmt.percent_text(data.steps_failed, data.steps_total) }} {{ fmt.percent_text(data.steps_skipped, data.steps_total) }} {{ fmt.percent_text(data.steps_pending, data.steps_total) }} {{ fmt.percent_text(data.steps_undefined, data.steps_total) }} {{ fmt.percent_text(data.scenarios_passed, data.scenarios_total) }} {{ fmt.percent_text(data.scenarios_failed, data.scenarios_total) }} {#- Run-level features, both parts - never the row count above. #} {{ fmt.percent_text(data.features_passed, data.features) }} {%- endmacro -%} {#- --------------------------------------------------------------------------- The whole table: the macro all four pages call. rows REQUIRED. An iterable of row mappings. Empty, none, absent or a value that is not an iterable of rows - a bare number, a string, a mapping - all render a table with a complete header and no body rows, rather than raising or spelling a string out one character per row. first_column_label REQUIRED. 'Feature' or 'Tag'. totals OPTIONAL, default none. Supplying it renders the footer; omitting it renders no tfoot at all, which is the two detail pages. An empty mapping is a supplied mapping and renders a footer of zeros: presence decides, not content. sortable OPTIONAL, default true. True emits the id the tablesorter initialisation binds to, plus the hover class. THE TWO DETAIL PAGES MUST PASS false - their reference tables carry neither, and a single row has nothing to sort. --------------------------------------------------------------------------- -#} {%- macro stats_table(rows, first_column_label, totals=none, sortable=true) -%} {%- set key_column = first_column_label|default('', true)|string|trim -%} {%- set candidate = rows|default(none) -%} {#- A string is iterable one character at a time and a mapping one key at a time; neither is a row sequence, and both are excluded before the copy rather than after it. -#} {%- set items = candidate|list if (candidate is iterable and candidate is not string and candidate is not mapping) else [] -%} {%- set is_sortable = sortable|default(false, true) -%} {#- Presence of the mapping decides the footer, so an empty one still renders a footer and an absent one still renders none. -#} {%- set footer_totals = totals|default(none) -%} {#- The scroll region's accessible name. It names what the table holds rather than repeating the word "table", which a screen reader already announces from the role, and it degrades to the generic form when the caller supplied no column label. -#} {%- set wrap_label = ('Step and scenario statistics by ' ~ key_column|lower) if key_column else 'Step and scenario statistics' -%} {#- The three call sites below each supply the indentation of the fragment they place, per the note in stats_header. -#}
{#- The accessible name, first child of the table as a caption must be, in the vendored visually-hidden class so nothing new renders. It names the table by the column that identifies its rows - "Feature statistics" or "Tag statistics" - which is the one thing that distinguishes this table's four call sites from one another. A caller that supplied no label still gets a caption rather than an unnamed table. #} {{ (first_column_label|default('', true)|string|trim) ~ (' statistics' if (first_column_label|default('', true)|string|trim) else 'Statistics') }} {{ stats_header(first_column_label) }} {%- for item in items %} {{ stats_row(item) }} {%- endfor %} {%- if footer_totals is not none %} {{ stats_footer(footer_totals, items|length) }} {%- endif %}
