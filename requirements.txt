# =============================================================================
# testinium-qa - RUNTIME dependency manifest (Python 3 / Flask)
# =============================================================================
# Python counterpart of the Maven dependency contract declared in the
# `dependencies` section of pom.xml [pom.xml:L34-L81].
#
# POM STATUS. pom.xml is a READ-ONLY PARITY CONTRACT (AMB-4): it is
# never compiled, never resolved by Maven and never edited. It is read
# statically as the authoritative record of every version, plugin setting and
# threshold that this port mirrors. No Java toolchain is required to install,
# run or verify this project.
#
# MANIFEST SPLIT. The dependency surface is deliberately divided in three:
#   requirements.txt       THIS FILE. The eleven RUNTIME distributions the
#                          Flask application itself needs to serve the ported
#                          pipeline surface (clone, run tests, generate and
#                          publish the report artifacts).
#   requirements-test.txt  The BDD / test HARNESS distributions - the Python
#                          counterparts of the eight Maven coordinates
#                          [pom.xml:L36-L81] and of the Surefire plugin
#                          [pom.xml:L18-L20]. They are intentionally NOT
#                          declared here.
#   pyproject.toml         The optional quality tooling, declared as an extra
#                          dependency group rather than as a requirement line.
#
# There is deliberately NO `-r requirements-test.txt` include line in this
# file: the two manifests stay independent so a production image can install
# the runtime set on its own. The Makefile `install` target installs both
# explicitly, and so does the Dockerfile:
#     pip install -r requirements.txt -r requirements-test.txt
#
# PINNING POLICY. Every distribution is pinned with the exact-match operator
# `==`. No version ranges, no floating or unbounded specifiers, no compatible-
# release specifiers, no environment markers, no extras and no placeholder
# versions. Deterministic resolution is the Python analogue of the fixed Maven
# coordinates in pom.xml. Hash pinning is intentionally not used: it would
# require a lock workflow this project does not define.
#
# VERSION PROVENANCE. Every version below was verified in a LIVE CPython
# 3.14.6 environment by resolving and installing the distribution and reading
# back the installed distribution metadata - no version string here is a guess
# or a placeholder. The interpreter itself is pinned in `.python-version`
# (3.14.6) and by the `requires-python` constraint in pyproject.toml; together
# they are the analogue of the maven.compiler.source and maven.compiler.target
# language level 8 declared at [pom.xml:L12-L13].
#
# Purpose annotations sit on their own comment lines above each entry and are
# quoted from the "Python Runtime Dependencies" inventory.
# =============================================================================

# click: command-line interface backing the `flask` commands.
click==8.4.2
# blinker: signal support used by Flask.
blinker==1.9.0

# The six entries after Flask are Flask's own transitive stack. They are

# dependency set instead of relying on transitive resolution.

# --- Production WSGI server --------------------------------------------------
# gunicorn: production WSGI server; Flask's development server is not
# production grade. Tuned by gunicorn.conf.py and entered through wsgi.py.
gunicorn==26.0.0

# --- Configuration -----------------------------------------------------------
# python-dotenv: loads `.env`, one link in the configuration precedence chain
#   explicit constructor argument, then environment variable, then the `.env`
#   file, then configuration.properties, then the hard-coded source default.
# The Java `.properties` link of that chain needs no dependency at all: the
# standard library `configparser` parses it once a synthetic default section
# is supplied, so configuration parity costs zero extra distributions.
python-dotenv==1.2.2

# --- Cross-origin handling for the report-retrieval endpoints ----------------
# flask-cors: cross-origin handling for the routes that serve the generated
# artifacts - cucumber.json, cucumber-reports.html, rerun.txt, the PrettyReports
# directory, the screen shots and the error shots, all kept under `target/`.
flask-cors==6.0.5

# --- API schema validation ---------------------------------------------------
# pydantic: request and response schema validation in app/api/schemas.py.
pydantic==2.13.4
