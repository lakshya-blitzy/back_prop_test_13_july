# DEFECT D6 / AMB-8 - FORCED CORRECTION (the ONLY one in this migration)
# -----------------------------------------------------------------------------
# pom.xml declares io.cucumber:cucumber-junit TWICE, at two different versions:
#
#     io.cucumber:cucumber-junit  7.2.3  scope test   [pom.xml:L60-L65]
#     io.cucumber:cucumber-junit  7.3.4  no scope     [pom.xml:L76-L80]
#
# A Python requirements file CANNOT express two versions of one distribution.
# Two exact pins for the same distribution name are a hard resolution conflict,
# not a last-one-wins override the way a POM treats them, so the duplicate
# simply cannot be carried across in any form.
#
# Why collapsing it is nevertheless EXACT rather than lossy: Maven had already
# resolved this to the last declaration alone, version 7.3.4. The redundant
# earlier declaration never affected the build's behaviour, only its text.
# Pinning one Python distribution therefore reproduces the RESOLVED behaviour
# precisely; the only thing that disappears is the redundant declaration
# itself. Both declarations are answered by the single pinned pytest-bdd==8.1.0
# above.
#
# This is the ONE defect in the entire migration that is CORRECTED rather than
# preserved, and it is corrected only because the file format makes preserving
# it impossible. Every other catalogued defect is PRESERVED as the default and
# is merely made overridable through configuration: the tag expression that
# selects zero scenarios, the never-failing non-gating build, the Examples
# tables that bind to only the third Scenario Outline, the password value fed
# into the username field, the English comment sitting beside the French
# assertion, the two contradictory clone URLs, the non-discoverable CI
# filename, and the duplicate scenario name that silently destroys one
# scenario's coverage. None of those is fixed here.
#
# Recorded in full, together with the preservation status of every other
# defect, in docs/migration-parity.md.
# =============================================================================


# =============================================================================
# WHY NO PYTHON REPORTING PLUGIN IS NEEDED
# -----------------------------------------------------------------------------
# me.jvt.cucumber:reporting-plugin:7.2.0 [pom.xml:L66-L70] needs no direct
# Python analogue. pytest-bdd 8.1.0 ships a NATIVE Cucumber JSON writer,
# exposed as `--cucumberjson`, verified to emit the same schema the Jenkins
# cucumber publisher consumes: tag values without the leading marker character,
# and the feature, scenario and step key sets the publisher expects. That
# single fact is what makes report parity achievable without writing a report
# serializer from scratch.
#
# The four report artifacts are therefore produced as follows:
#   cucumber.json          pytest-bdd's native `--cucumberjson` writer
#   cucumber-reports.html  pytest-html with `--self-contained-html`
#   rerun.txt              derived deterministically from the JSON report
#   cucumber/ directory    derived deterministically from the JSON report
#
# Deriving the last two from the JSON is more faithful than a terminal
# reporter would be, because the Java plugin likewise rendered its report
# directory from the JSON rather than writing terminal output.
# =============================================================================

# DELIBERATELY NOT DECLARED HERE
# -----------------------------------------------------------------------------
# psutil        NOT required, and intentionally absent. pytest-xdist declares
#               psutil only as an OPTIONAL extra, never as a hard dependency,
#               so `pip check` is clean without it. The `-n logical` option
#               degrades gracefully in pytest-xdist 3.8.0: it guards its
#               `import psutil` with an ImportError handler and falls back to
#               affinity-based CPU detection, which its own `-n` help text
#               documents as "requires psutil, falls back to 'auto'". Verified
#               empirically on this stack -- with psutil uninstalled,
#               `-n logical` still brings up its workers and the run passes.
#               Older pytest-xdist releases did abort in that situation; 3.8.0
#               does not. Do not re-add it as a tenth pin.
#
# Runtime stack Flask, Werkzeug, Jinja2, MarkupSafe, itsdangerous, click,
#               blinker, gunicorn, python-dotenv, flask-cors and pydantic are
#               declared in requirements.txt and reached through the
#               `-r requirements.txt` include above. Never re-declare them
#               here: each distribution is declared in exactly one manifest.
#
# Quality tools ruff, black, mypy and pytest-cov belong to the optional
#               dependency group in pyproject.toml, not to this manifest.
#
# Gherkin terminal reporter
#               Not a separate distribution, and never enabled by default. It
#               is mutually exclusive with xdist: pytest-bdd raises an
#               exception during configuration and aborts the run when both are
#               active. The serial `make test-pretty` target is the escape
#               hatch, and pytest.ini's default option set omits the flag.
#
# Also excluded: any second BDD engine (behave, radish, pytest-splinter), any
# second HTTP client, any second synthetic-data library, any cucumber-* or
# other Java artifact, any Node.js package, and any tooling related to .java
# sources. No Java toolchain is required to install this manifest or to run
# this project's verification.
