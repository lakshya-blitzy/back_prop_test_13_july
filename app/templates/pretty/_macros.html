It renders no page, is never rendered standalone and is never a target of app/reporting/pretty_reports.py, which renders only the six page templates in this folder - overview_features, overview_failures, overview_steps, overview_tags, feature and tag. The underscore prefix is the folder's convention for a helper. Consumers import it; they never include it: {% import 'pretty/_macros.html' as fmt %} and then call fmt.duration_cell(...), fmt.count_cell(...) and the rest. The plain import form is deliberate. No macro here reads an ambient template variable - every value a macro needs arrives as an argument - and that restraint is what lets the same call render identically from a page template, from _stats_table.html and from _element_tree.html. WHY THIS FILE EXISTS The duration rule below has two structurally different consumers: the sorted duration cell in a statistics table, which carries the raw nanosecond count on a sort attribute, and the inline duration span in the element tree, which carries no such attribute. A report whose table disagrees with its own tree is wrong in a way no reader can diagnose, so the rule lives in exactly one place. This is the same discipline app/utils/paths.py applies to artifact paths and app/templates/partials/status_badge.html applies to status normalisation. THE COLLAPSE-ALL CONTROL IS HERE FOR THE SAME REASON. Both detail pages - feature.html and tag.html - carry the pair TWICE, once above the element tree and once below it, which is measured on the clean reference pages of both kinds. That is four blocks whose markup must be identical: they address the same regions through the same script, so a control that drifts on one page is a control that behaves differently on two pages of one report. One macro, four call sites, no drift. It lives in this file rather than in either page because neither page may import the other - a page template extends the layout and imports helpers, and two pages importing each other is a dependency this folder does not have. --------------------------------------------------------------------------- THE DURATION RULE - MEASURED, NOT DOCUMENTED --------------------------------------------------------------------------- Every pair below was read out of the committed report tree at the pinned reference revision. The four detail pages are free of merge markers and are the trustworthy source; the overview pages splice two different runs, so their structure is readable but their arithmetic is not. nanoseconds rendered 0 0.000 1000000 0.001 67000000 0.067 85000000 0.085 1648750000 1.648 5668000000 5.668 9533750000 9.533 15841000000 15.841 20400000000 20.400 24654000000 24.654 62051000000 1:2.051 100186000000 1:40.186 Three rules follow, each with its proof in that table: 1. MILLISECONDS TRUNCATE. They never round. 1648750000 ns is 1.64875 s and renders 1.648, not 1.649; 9533750000 ns is 9.53375 s and renders 9.533, not 9.534. Two independent witnesses, so this is the rule and not an artefact of one sample. The floor division below is what implements it, and it must not be "improved" into rounding. 2. UNDER ONE MINUTE - S.mmm. Exactly three decimal places always, and no padding on the seconds: 0.001, 0.067, 20.400. 3. AT OR OVER ONE MINUTE - M:S.mmm, and the seconds field is NOT padded. 62051000000 renders 1:2.051, not 1:02.051. This is unusual, it is measured twice over, and it is the single easiest thing in this file to get wrong. Note the asymmetry with percentages, which DO round: 2 of 19 steps renders 10.53% in the reference footer, where truncation would give 10.52%. Duration truncates, percentage rounds. Neither is a typo and they must not be unified. An hours-scale value extends the same pattern as H:MM:SS.mmm, with minutes and seconds padded to two digits because a bare colon-separated triple is ambiguous otherwise. That branch is DERIVED, NOT MEASURED - the reference suite contains no run of an hour, so no sample pins it - and it should be confirmed against a regenerated clean baseline if one is ever produced. --------------------------------------------------------------------------- WHICH FORMS CARRY THE SORT ATTRIBUTE, AND WHICH MUST NOT --------------------------------------------------------------------------- The raw nanosecond count travels on the data-value attribute of a statistics cell, and only there. The vendored table-sorting script reads that attribute instead of the cell text, which is the only reason 1:40.186 sorts above 24.654 rather than below it lexically. Three forms, three different answers: duration_cell carries data-value with the RAW nanosecond integer, never the human string. duration_span carries NO data-value. Measured: 27 inline duration spans in the reference feature page, not one with the attribute. The difference is intentional in the generator and is not tidied up here. duration_total_cell carries NO data-value, because a footer total is not a sortable row. It is a separate macro rather than a flag on duration_cell so that emitting the attribute there is not a mistake a caller can make - the string does not appear in it. --------------------------------------------------------------------------- THE MACROS --------------------------------------------------------------------------- duration_value(ns) The canonical nanosecond count as text, or the empty string when there is no usable duration. This is the coercion every other duration macro shares, exported because duration_cell's sort attribute is exactly its answer and because a test can then pin the coercion on its own. duration_text(ns) The human duration per the three rules above. The empty string when ns is absent or none - not 0.000, which is a real and different reading. A step that was skipped may legitimately carry no duration at all: in the reference result set three steps are skipped and only one of them has the key, so both shapes reach this macro and neither may raise. duration_unavailable() The fallback a duration CELL shows when there is no usable duration: an em dash for a sighted reader and visually hidden words for a screen reader. One macro, because two cells show it. duration_cell(ns, extra_classes='') The sortable statistics cell. Omits the sort attribute entirely, rather than emitting an empty one, when there is no duration - and shows duration_unavailable() in the cell, because an empty cell reads as a rendering fault rather than as missing data. duration_span(ns) The inline duration in the element tree. NO fallback here, and that asymmetry is deliberate: an empty CELL is a visible blank box in a grid of numbers, which reads as a rendering fault, while an empty inline span takes no room at all in the flow beside a brief that already names the element and its state. A dash there would read as content rather than as an absence. duration_total_cell(ns, extra_classes='') The footer total, with the same cell fallback as duration_cell. count_cell(value, status_class='') A numeric statistics cell. The status class is applied ONLY when the count is non-zero: the reference emits a bare cell for a zero, fourteen times over, so a coloured zero would be a visible parity break. A blank status class also yields a bare cell, and none or absent counts as zero. total_cell(value) The Total column, which always carries its class - including for zero, where count_cell deliberately does not. percent_text(part, whole) A percentage to exactly two decimals, rounded. A zero or missing whole answers 0.00% rather than failing: the reference footer carries 0.00% cells, and a report is what a reader turns to when a run has gone wrong, so arithmetic on an empty set must render rather than take the page down. status_label(status) The capitalised label only - Passed, Failed, Skipped, Pending, Undefined, and Untested, Ambiguous or Unknown for the tokens the generator's own palette does not cover. It returns text and not a cell because the reference puts the same label in cells whose class varies, so the caller owns the cell and its class. timestamp_text(value) A scenario start timestamp, rendered exactly as the result model carries it. The empty string when absent: a Background element carries no start timestamp at all, along with no id and no tags. collapse_all_control() The expand-all / collapse-all pair of the two detail pages, in the measured Bootstrap wrapper. The one macro here that emits a control rather than formatting a value; its own note below records why the two controls are buttons, what drives them and why neither carries aria-expanded.
