Given, When, Then, And and But all work; But never occurs in this suite but is not special-cased. --------------------------------------------------------------------------- MACRO 2 - step_row(step, uid=none, extra_classes={}, filterable=true, duration_fallback=none, inline_args=false, show_location=false, embeddings=none) --------------------------------------------------------------------------- step REQUIRED. A caller-supplied token that makes the detail region's id unique across the page. See DETERMINISM below for the derivation and for what happens when it is omitted. Any type is accepted; it is read as text. extra_classes OPTIONAL, default an empty mapping. Extra class tokens per slot. See SLOTS below. A plain string is also accepted and means "apply these to the step container only", which is the common case. filterable OPTIONAL, default true. When true the step container carries the two behaviour hooks the report script filters on, so the step is the unit the status filter hides. A caller whose scenario container is already the filter unit passes false, because hiding an element hides its whole subtree and a nested second registration would be redundant. duration_fallback OPTIONAL, default none. When true the resolved step function's location is rendered inside the detail region as plain data, in an inline element that wraps - see the class note below, since a location is one unbreakable token and overflows a narrow viewport without it. Nothing is asserted about its shape: it is a dotted path here where the original carried a method signature, and an undefined step has no location at all. embeddings OPTIONAL, default none. Screenshot embeddings for the detail region, handed straight to the lightbox partial. Embeddings live on the SCENARIO's after-hook list, never on a step, so the calling template decides which step - if any - carries them; passing that list in unchanged is supported. SLOTS - the keys extra_classes may carry, each a string of class tokens appended after this project's own class on that element: step keyword name badge duration detail error args arg A missing slot, a blank slot and a non-string slot are all "no extra classes". Runs of whitespace inside a caller's value collapse to single spaces, so a class list assembled across several template lines cannot land a newline inside an attribute. Two slots are worth naming: arg goes on each highlighted argument, and is the ONLY class those elements carry. The stylesheet declares no per-argument class, so the pretty template set passes the vendored generator's own argument class here to pick up its styling. No class name is invented for it. badge styles the status badge, and the one sentinel in this file: the value boolean false - not the string, not none, not a blank - suppresses the badge entirely. The signature above is fixed, so a surface that does not want a badge says so here. Rendering it is the default, deliberately: the reports artifact test requires every step's status to appear in the page. RENDER-NOTHING CONDITIONS - A step that is not a mapping renders the empty string. An EMPTY mapping does render, as a step with no keyword, no name and an unknown status, because silently dropping a step would misreport the run - and a report is what a reader turns to precisely when a run has gone wrong. - The toggle and the detail region are emitted ONLY when the detail region would have content: matched arguments to list, a location to show, an error message, or a screenshot. An expander controlling nothing is an accessibility defect and it pollutes the artifact page, so neither element appears. - The duration element is omitted when the result carries no usable duration and no fallback was supplied. - The argument list, the location and the error block are each omitted when their own value is absent, blank or unusable. THE INPUT MODEL - measured against the reference report, not assumed. Every field is optional and every one is type-tested before use: keyword "Given " etc, with the trailing space. Trimmed for display. line the step's line in its feature file. Feeds the detail id when no uid is supplied. name the step text, already substituted for an outline row. match { location, arguments }. Both optional: an undefined step's match is an empty mapping and carries neither. arguments is a list of { val, offset } where val INCLUDES its surrounding quotation marks and offset is a zero-based character offset into name. result { status, duration, error_message }. status is lower case and is normalised by the badge partial, never here. duration is a NANOSECOND INTEGER and is INDEPENDENTLY OPTIONAL FOR EVERY STATUS - the reference carries one skipped step with a duration and another without, so its presence is never inferred from the status. It is rendered as seconds to three decimal places, never as a bare nanosecond count, with the exact integer preserved in advisory text so a test can read the model value back out of the page. Zero is a real value and renders; a negative, a float, a boolean and a non-number render nothing. error_message appears only on a failure, spans many lines, and carries assertion text and a traceback. This macro reads ONLY step.* - never a scenario's id, tags or start timestamp. That is not tidiness: in the reference the eight elements are four backgrounds and four scenarios interleaved, so the same background is rendered before each scenario, and a background element carries none of those three keys. Reading only the step is what lets one macro serve both. No partial in this folder renders a timestamp either; that belongs to the templates that own a scenario or a feature. Step docstrings and step-level data tables are deliberately absent, and this is a settled exclusion rather than work left undone: the suite contains neither - all ten feature files were searched - and the result model carries neither, so rendering them would be an addition nobody asked for. Such a key arriving anyway is ignored rather than treated as an error. DETERMINISM - the emitted structure has to be identical for identical input, so the detail region's id is derived, never generated. There is no unpredictable source, no unique-value generator and no counter whose value depends on the order pages happen to be rendered in. The id is this project's own prefix followed by the uid when one is supplied, and by the step's line otherwise; characters outside letters, digits, the hyphen and the underscore become hyphens, and the prefix guarantees the result is a usable id. Two consequences for callers: the same step with the same uid always yields byte-identical ids, and PAGE-WIDE UNIQUENESS IS THE CALLER'S JOB - a page rendering a step more than once, or rendering two features whose steps share line numbers, must pass a uid that distinguishes them. THE THREE SURFACES, AND WHAT THEY FORBID ---------------------------------------- This markup is rendered into three places whose asset rules do not agree: 1. The single self-contained page app/reporting/html_report.py writes to the reports HTML artifact, which carries no external asset reference of any kind - the reference artifact has exactly one reference in 1,440,365 bytes, and it is an inline data URI. 2. The report tree app/reporting/pretty_reports.py writes, opened straight from a Jenkins workspace, where every reference has to resolve inside that tree. 3. The Flask views under view/, which extend base.html - and it is base.html, never this file, that resolves the stylesheet and the behaviour script for them. So, with no exception: this partial builds no application endpoint URL, calls no framework URL-building helper, references no stylesheet, behaviour script, image file or sibling page, and contains no absolute or protocol-relative web address. Anything link-shaped a caller needs is passed in as text the calling template has already built; with none passed in, the step name is plain text. NO LINK DETECTION, ANYWHERE. No automatic link-detection filter is applied to any value - not the error message, not the location, not the name. This is not a preference. The reference failure text contains a literal web address of its own, and the reference generator renders it as plain text inside a preformatted block with no anchor to it anywhere on the page. Detecting it would inject a genuine external reference into the self-contained artifact FROM DATA, which no reading of this template would ever reveal, and the artifact test that forbids exactly that would fail. ESCAPING - this file leans on the engine's own default escaping of HTML templates for every interpolated value and never declares a value pre-escaped or trusted markup. Assertion text and Selenium messages carry angle brackets, quotation marks, apostrophes, braces, tabs and characters outside ASCII, and every one of them is escaped on the way out. The stylesheet handles the wrapping and the monospacing of what remains. WHAT IT DELIBERATELY DOES NOT EMIT - No icon markup, in any vocabulary. The expander glyph is supplied by the stylesheet as generated content, and the icon fonts ship only inside the generated report tree, so a glyph element here would be a blank box on two of the three surfaces. The generator's own icon class names stay reachable through extra_classes. - None of the three boolean state attributes the stylesheet reads, and none of the three state classes the report script sets at run time. The stylesheet reads the absence of those attributes as expanded, visible and closed, so server output always describes the fully expanded page. That is what keeps both artifacts legible with scripting turned off and correct on paper, and it is why the toggle is authored expanded. - None of the vendored generator's own collapse attributes, even though the reference generator uses them. The report script is the single owner of interactivity across all three surfaces, and the vendored behaviour script is loaded on only one of them. - No presentation attribute on any element and no embedded stylesheet block: presentation belongs to main.css, which one writer inlines and the other copies. - No class outside the set main.css declares, and no new name invented in its namespace. The location is a plain inline element carrying the stylesheet's own metadata-value class, and deliberately not either of the two elements that would suggest themselves for a dotted path: those are styled bare by the vendored stylesheets inside the generated report tree, which would give the location one appearance there and another on the two surfaces that never load them. A class out of main.css has no such asymmetry, because main.css reaches all three - inlined into one artifact, copied into the other, linked by the views. It is also what makes the location WRAP: a location is a single unbreakable token, and measurement at a 480px viewport showed that without that class one such token pushes the whole document into horizontal overflow. ACCESSIBILITY - a real button for the toggle, non-navigating, carrying its expanded state and the id of the region it controls, and named in words because its glyph is generated content and therefore has no text of its own to be named by.
