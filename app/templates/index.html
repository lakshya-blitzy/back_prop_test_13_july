{#- =========================================================================== index.html - the GET / landing page of the read-only report viewer. =========================================================================== ROUTE CONTRACT - one row of the HTTP surface, and the whole of it: servability and modification time of each of the four report artifacts, with links. Status 200 always, including before any run has ever happened. This is the only report-ish route with no data-availability precondition. The four report views answer 404 when the JSON report is absent, unreadable or unparseable; this page renders on a completely empty workspace, so its empty state is the normal first-run experience rather than an error. Nothing here is a failure to report - an artifact that has not been generated yet is simply marked as such. RENDER CONTEXT - the view function passes exactly one variable: artifacts An ordered sequence of artifact descriptors, in the order of ARTIFACT_SPECS in app/utils/paths.py (the HTML report, the JSON report, the rerun manifest, then the PrettyReports directory - the plugin order of the original Java runner). Each descriptor exposes six members, addressed by name: label Required. Human-readable name, e.g. "Cucumber HTML report", "Cucumber JSON", "Rerun manifest", "PrettyReports tree". route_name Required. The value to pass as the artifact route's name argument for this artifact. The view function decides it: the three single-file artifacts are named by their own key, while the PrettyReports tree is named by the overview PAGE inside it and never by the directory. The route answers the directory's two authorized spellings with a redirect to that page precisely so a browser's base URL ends up inside the tree, where the page's relative stylesheet, script, image and sibling-page references resolve; a link to the directory would deliver the same bytes under a base URL one level too high and break all of them. relpath Required. ArtifactSpec.relpath - the repository- relative path, for display only. servable Bool. True only when a request for route_name would be served right now - the view function establishes it by opening the artifact through the same authority the artifact route serves from, so a link offered here resolves. Being on disk is NOT the same question: a symlinked or hard-linked artifact, and a report tree whose overview page was never written, are all present and all refused by that route. modified_iso str or None. Millisecond-precision UTC ISO-8601 ending in a literal Z, e.g. 2022-09-07T13:37:26.297Z, which is the form the artifacts themselves carry. Used verbatim as the datetime attribute. modified_display str or None. The human-readable form, e.g. "07 Sep 2022, 15:39", matching how the generated report tree renders build dates. The three optional members are read through default(), so a descriptor that omits one, or carries None or an empty string, renders a plain textual fallback instead of emitting a literal None or an empty datetime attribute. The three required members are the row's identity and are not defaulted: a descriptor without them describes no artifact. This template computes nothing. It performs no filesystem access, formats no timestamp, decides no availability and holds no path literal of its own: servability, the name to link and both timestamp forms are all settled by the view function, and every path string it displays arrives in the context from the path module that owns it. URLS - built with url_for only, never by hand. The one endpoint used here is web.artifact, per the endpoint contract in base.html and app/web/__init__.py. An artifact that is not servable is rendered without a link, because a link that is certain to 404 is worse than no link. Its card reads "Not generated yet" whichever reason the route would refuse it: this page distinguishes no causes, exactly as the 404 itself does not. NO REPORT DESTINATION IS OFFERED FROM THIS PAGE, and that is a decision rather than an omission. The four report routes share one data-availability rule - results that are absent, UNREADABLE or UNPARSEABLE all answer 404 alike - so a link to any of them is actionable only when the results are known to be usable. This page cannot know that. It is handed servability and modification times, nothing else, and servability is not usability: a complete artifact set whose results file will not parse answers 404 on every report route while every card above still offers that artifact as a download. Gating a report link on servability would therefore put a certain-404 back on the one page a reader reaches before anything has run, which is the defect the shell was corrected for; and a template cannot settle the question itself, because it cannot parse the results file and may not name one artifact - those names belong to app/utils/paths.py and no template restates one. So the shell offers no report destination here (base.html, ACTIVE NAVIGATION), and neither does this body. What would change that is one context key: a boolean from the view function, true only when the results file was read and parsed into a usable feature list - the same operation the report routes perform before answering 200. Adding it belongs to app/web/routes.py, and with it in the context this page would emit the two report links under that key and nothing else would need to change. Until then the rendered report the reader can open from here is the HTML artifact itself, linked in its card above like every other artifact this viewer can serve. CLASSES - app/static/css/main.css, used as written there: tqa-artifacts is a responsive grid list, tqa-artifact one card in it, tqa-artifact-missing the warning variant, tqa-empty the guidance box, with tqa-link and tqa-timestamp for the anchor and the time. No class is invented here and no style is inlined. Servability is never signalled by colour alone: every card states its condition in words as well. Headings start at h2. base.html renders the page's single h1 from the title block, so this template must not emit another one. PROHIBITIONS honoured, beyond those base.html states for every child: no control that starts, or appears to start, a test run - runs are started from the command line; no result counts, chart or status summary, which belong to the report overview and the summary route; and no reference of any kind to the per-worker intermediates, which are never reachable over HTTP. -#} {% extends "base.html" %} {% set active_nav = "index" %} {% block title %}Report artifacts{% endblock %} {% block content %}
