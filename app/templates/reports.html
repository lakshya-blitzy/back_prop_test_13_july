Where these artifacts come from

The four report artifacts are the four report plugins the test runner declares. Each declaration names the output path it writes to, and those are the paths listed above:

Cucumber HTML report
html:target/cucumber-reports.html
Cucumber JSON report
json:target/cucumber.json
Rerun manifest
rerun:target/rerun.txt
Pretty reports
me.jvt.cucumber.report.PrettyReports:target/cucumber

Screen shots are produced for your tests if you enable them, and error shots are produced for your failed test cases, so either directory can legitimately be missing after a run that went perfectly well. Everything under target/ is rewritten by every run, which is why an artifact listed as not generated yet is an ordinary state rather than a fault.

The test stage is non-gating by design: a run that selects no scenarios and a run that records failing scenarios both complete successfully, and the artifacts above are published either way.

The Cucumber HTML report is self-contained and carries its own styling. It is served exactly as the test toolchain wrote it and is never re-rendered here, so what it shows can never drift from what that toolchain produced.
