Nothing is rendered for it - no placeholder and no broken image. --------------------------------------------------------------------------- THE SCENARIO INDEX - the sharpest rule on this page --------------------------------------------------------------------------- The scenario route's second key is the scenario's zero-based position AMONG THAT FEATURE'S SCENARIO ELEMENTS, which is not its position among the elements. In the reference feature the four scenarios stand at element positions 1, 3, 5 and 7, so their keys are 0, 1, 2 and 3. So the derivation below walks the elements IN ORDER and carries a counter: each element is recorded in place, and an element whose type is "scenario" takes the counter's current value before the counter advances. A loop index over the raw elements would mis-key every link as soon as a background precedes a scenario, which in this suite is always. The repeated backgrounds are never reordered, deduplicated or collapsed either: the results file's structure has to be deterministic for identical input, and the background repeated in the same position is part of that structure. It is also true to the run - a background genuinely executes once per scenario. --------------------------------------------------------------------------- AGGREGATION RULES - the same definitions view/overview.html applies --------------------------------------------------------------------------- This page and the overview are two presentations of one calculation, so a reader comparing them can never be shown two different answers. The precedence order, the counting rules and the duration and timestamp formatting below are the overview's, name for name: 1. Step counts Every step of every element is counted, backgrounds included, because a repeated background genuinely ran once per scenario. Each step's status is normalised through the status partial, the project's single normalisation point. 2. Scenario The worst status among that scenario's OWN steps, by the status precedence declared below, highest first: failed, undefined, ambiguous, pending, skipped, untested, passed. An element with no steps is unknown. 3. Feature The same precedence applied across the steps of ALL this status feature's elements, backgrounds included. 4. Duration The sum of the duration values that are PRESENT, in nanoseconds, rendered as seconds to three decimals. With no duration key present at all the total is unknown rather than zero, and renders an em dash. 5. Scenario The number of elements whose type is "scenario", and NEVER count the element count, which double-counts every feature's scenarios in this suite. --------------------------------------------------------------------------- VOCABULARY AND PROHIBITIONS --------------------------------------------------------------------------- HEADINGS - base.html renders this page's single h1 from the title block, so the title block below carries the FEATURE'S OWN NAME and the content opens at h2 and descends without skipping a level.
