{#- --------------------------------------------------------------------------- partials/status_badge.html - one status token, as text or as a badge. --------------------------------------------------------------------------- One of the three shared partials, rendered into all three surfaces: the single self-contained artifact page, the generated report tree and the HTTP views. Status presentation is its whole concern. API - imported rather than included, and always without the calling context, so every value a macro needs arrives as an argument: {% from 'partials/status_badge.html' import status_badge, status_token %} {% import 'partials/status_badge.html' as badge %} status_token(status) answers the normalised token as text and emits no markup. status is REQUIRED and may be anything at all: it is trimmed, folded to lower case and answered as that token when it is one of STATUS_TOKENS, as STATUS_UNKNOWN otherwise. The fold is total and cannot raise, so none, a number, a container and an undefined name all answer "unknown". status_badge(status, label=none, extra_classes='', title=none) renders one span carrying that token on data-report-status. A label that is absent or blank renders the token capitalised, since the text content is the badge's accessible name and an empty one names nothing; extra_classes appends class tokens after tqa-badge, runs of whitespace collapsed; an absent or blank title omits the attribute altogether. Exported top-level names, reachable as badge.NAME: STATUS_TOKENS, the seven tokens the result model produces in reading order; STATUS_UNKNOWN; and STATUS_READING_ORDER, those seven with the fallback last, which a template iterates to present statuses in a fixed order. CONSTRAINTS THAT CANNOT BE READ OFF THE CODE - The single place a status is normalised for presentation. The seven tokens mirror the data-report-status enumeration in main.css, which has no rule for "unknown", so such a badge resolves the neutral grey fallback of the status custom properties. - No URL of any form and no stylesheet, script, image, sibling-page or endpoint reference, because the artifact page carries no external reference at all; automatic escaping carries every value, nothing is declared trusted markup, and every argument is made total because the tests render under a strict undefined policy. - No control here, so no mutable ARIA mirror is authored - no aria-expanded, aria-pressed or aria-hidden - and none of the three runtime classes report.js writes - report-is-collapsed, report-is-filtered-out, report-lightbox-is-open - appears either; main.css alone reads those, and their absence is the expanded, visible, overlay-closed page. data-report-status is classification rather than state, and it is the only status hook: colour, print rules and the status filter all read it, while a filter hook belongs on the row that hides as a whole rather than on a badge inside one. - No widget and no live-region role: the text is the accessible name, and a finished result must not be announced as a new one. -#} {#- ---- the presentation status vocabulary, written down exactly once ------- A top-level assignment is EXPORTED from a template, so these three names are reachable as badge.STATUS_TOKENS, badge.STATUS_UNKNOWN and badge.STATUS_READING_ORDER wherever this file is imported under a name, and the macros below resolve them from this module's own namespace even when the import deliberately carries no calling context. STATUS_TOKENS is quoted from the data-report-status enumeration in app/static/css/main.css: a token added to the result model has to be added there too, or a badge would carry a hook the stylesheet cannot colour - but it is added HERE FIRST, because this is the sequence every surface orders its own output by. STATUS_READING_ORDER is built from the other two rather than restated, so the fallback cannot go missing from the presentation sequence and the sequence cannot disagree with the fold. It is a plain list of plain strings, which is what a caller's sequence tests, concatenations and mapping lookups expect. -#} {%- set STATUS_TOKENS = ('passed', 'failed', 'skipped', 'pending', 'undefined', 'untested', 'ambiguous') -%} {%- set STATUS_UNKNOWN = 'unknown' -%} {%- set STATUS_READING_ORDER = (STATUS_TOKENS|list) + [STATUS_UNKNOWN] -%} {%- macro status_token(status) -%} {#- The seven tokens and the fallback are read from the names above, so this macro carries no vocabulary of its own and cannot drift from the reading order its callers present results in. -#} {#- default(..., true) is what makes this total. It answers for an undefined name without ever reading it - so a strict undefined policy raises nothing - and folds none, the empty string and every other falsy value onto the same empty candidate. |string then accepts a number or a container without complaint. -#} {%- set candidate = status|default('', true)|string|trim|lower -%} {{- candidate if candidate in STATUS_TOKENS else STATUS_UNKNOWN -}} {%- endmacro -%} {%- macro status_badge(status, label=none, extra_classes='', title=none) -%} {%- set token = status_token(status) -%} {#- Split and rejoin rather than trim: it normalises the caller's own separators as well as the outer edges, so a class list assembled across several template lines cannot land newlines in the attribute. -#} {%- set extra = (extra_classes|default('', true)|string).split()|join(' ') -%} {%- set caption = label|default('', true)|string|trim -%} {%- set tip = title|default('', true)|string|trim -%} {{ caption if caption else token|capitalize }} {%- endmacro -%}
