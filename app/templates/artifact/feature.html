{#- --------------------------------------------------------------------------- artifact/feature.html - one feature of the single, self-contained HTML report artifact. --------------------------------------------------------------------------- It renders the feature's heading, status badge, tags, description and details, and delegates each background and scenario whole to artifact/element.html. There is no per-feature page on this contract and no navigation, because every feature is in the one document. API {% import "artifact/feature.html" as feature %} {{ feature.feature_block(feature_map, findex) }} feature_block(feature, findex, extra_classes='') feature is REQUIRED - one mapping from the model's feature list - and anything that is not a mapping renders the EMPTY STRING. findex is REQUIRED: the feature's zero-based index in that list, read as text and sanitised, and handed on unchanged to every element so their ids stay unique across the whole document. extra_classes appends class tokens to the root as a STRING, runs of whitespace collapsed. Every model field is optional and type-tested, so a sparse feature renders under the strict undefined policy the tests enable, and a feature with NO ELEMENTS renders cleanly and says so in words. CONSTRAINTS THAT CANNOT BE READ OFF THE CODE - The uri is DISPLAYED EXACTLY AS THE MODEL CARRIES IT: no prefix stripped, no directory rewritten, nothing turned into a link, nothing normalised. Normalising a feature URI belongs to app/utils/paths.py, and no template holds a path literal. The name is rendered as the data carries it too - the suite's own inconsistent titles are preserved rather than tidied - and the description keeps its leading indentation verbatim, which is why it is tested for content and never for presence. - Status is the ROLLED-UP value the writer supplies, never derived here and never rolled up from the elements; it is only passed through the badge partial's normaliser, which answers "unknown" for an absent one. - ELEMENT ORDER IS THE MODEL'S ORDER, unconditionally: no sorting, filtering, grouping, de-duplication or hoisting. A background REPEATS BEFORE EACH SCENARIO in this schema and every occurrence renders in its own position, because that repetition is both what the run did and part of the determinism the report contract requires. - Every id and name reference is composed from findex - never from the feature name and above all never from the feature id slug, two pairs of which collide in this suite. The feature id therefore appears in exactly one place, as text in the details list, and is never an id attribute, a name reference or a link key. - THE FEATURE ROOT IS NOT A FILTER UNIT. Its status is an aggregate of its elements and hiding a filterable element hides its whole subtree, so registering the feature would hide every passed scenario inside a feature rolled up to failed. data-report-status stands alone here as the stylesheet's accent and print hook, and the filter registers one level down, in artifact/element.html. - Inlined into a page that must open from a filesystem with no network, so no URL of any form, no stylesheet, script, image or sibling-page reference and no endpoint-builder call. This file inherits no shell template, carries no inline style or script, relies on automatic escaping and declares nothing trusted markup. - No control is emitted here - the per-scenario toggles and the page's own controls are the whole of this artifact's collapse behaviour - so no mutable ARIA mirror is authored; the accessible name and the heading relationship this file does emit are static semantics, which nothing maintains and main.css does not read. None of the three runtime classes report.js writes - report-is-collapsed, report-is-filtered-out, report-lightbox-is-open - appears either; main.css alone reads those, and their absence is the fully expanded, fully visible page. - The block is a section named by its own heading, so each feature is a region a reader can move between in a document holding all of them; the heading level is fixed here, one below the page title and one above the element headings. -#} {% import "artifact/element.html" as element %} {% import "partials/status_badge.html" as badge %} {%- macro feature_block(feature, findex, extra_classes='') -%} {%- if feature is mapping -%} {#- ---- the document-unique key -------------------------------------- Derived from the feature index, never generated: no counter, no unique value source, nothing whose result depends on the order pages happen to be rendered in, so identical input yields identical ids.
