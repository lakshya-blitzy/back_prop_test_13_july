Nothing here is shared with that folder except the partials named below. WHAT IT RENDERS. Two halves of the report header, in this order: 1. the run's provenance - what produced the report, on what runtime, on what machine, when it was generated and when the run started; 2. the run's tally - how many features, scenarios and steps there were and how they came out, with the earliest scenario start as the anchor. Both are read straight from the normalised result model. This template computes nothing: it counts nothing, derives no status, formats no timestamp and holds no path literal. The partial is imported without the calling context, which is what keeps its output identical on every surface it renders into. Its status_badge macro is deliberately not called here: a tqa-count is itself a status-coloured container in the stylesheet, and nesting a badge inside one would render a pill inside a pill and state the same status twice. Colour is never the sole carrier of meaning: every coloured count states its group and its status in words, so the block reads the same in greyscale, on paper and to a screen reader. That holds for an unrecognised key too - it keeps its own spelling, which is the informative part, and gains the state it was folded to in parentheses whenever the two differ, so a count reading "Steps bogus (unknown)" says in text exactly what its neutral tint says in colour. A key that differs only in case, folding onto a state it already spells, gains nothing and stays as it was written. The stylesheet pairs each status with a border style and a weight for the same reason, and it owns every colour - this file emits the attribute hook and not one colour of its own. Its print rules drop the tints and set one weight for every count, so the words are what carry a status onto paper. ORDERING is fixed rather than sorted: passed, failed, skipped, pending, undefined, untested, ambiguous, unknown, with any unrecognised key after them in sorted position - sorted case-sensitively, so that two keys differing only in case cannot fall back on the order the writer happened to insert them in. Identical input therefore yields identical structure, which is the determinism the report contract requires. The alphabetical sorting configured in the CI publisher is a display option of that publisher and imposes nothing on the artifacts, so nothing is sorted on its account. --------------------------------------------------------------------------- CLASS VOCABULARY - app/static/css/main.css, and nothing else --------------------------------------------------------------------------- tqa-meta and tqa-meta-item for the provenance grid, tqa-meta-label and tqa-meta-value for the pair inside each item, tqa-summary and tqa-count for the tally, tqa-timestamp for a time, tqa-empty for the empty state. No name is invented: the stylesheet carries no selector outside that namespace, so an invented class would render unstyled and silently. Two markup choices follow that stylesheet rather than convention. The provenance grid is a list, not a description list: tqa-meta-item is declared as a flex container, which makes each item a flex box rather than a list item and so generates no marker, while tqa-meta's own padding replaces the browser's list indent - whereas a dd would keep its 40px browser margin, which no rule in the stylesheet resets and which this file may not add. And the count itself sits in a b element because the stylesheet sizes exactly that element inside tqa-count and gives it tabular figures, so the digits of adjacent counts line up. WHITESPACE is cosmetic here and the block is written to tolerate whichever trim settings the writer's engine carries: no rendered element depends on a text node between two tags. The stylesheet separates a count from its label with a gap on the flex container rather than with a space in the markup, precisely because a whitespace-only text node between flex or grid items is not rendered at all. So the structure is identical in either mode; only the indentation of the emitted source differs. TIMESTAMPS are rendered exactly as the model carries them - millisecond precision, a literal trailing Z - as the machine-readable value of a time element and as its text. Nothing is re-parsed, reformatted or localised here, and no date library is reachable from this page. --------------------------------------------------------------------------- PROHIBITIONS, ALL OF THEM HONOURED --------------------------------------------------------------------------- This block is inlined into a page that must be readable from a filesystem with no network at all, so: no absolute, protocol-relative or content- delivery-network URL; no reference to a stylesheet, script, image, font or sibling page; no application endpoint URL, because this page is written to disk rather than served; and no icon glyph, because the icon fonts ship only inside the other generator's tree and are unreachable from here. The one style element and the scripts of the finished page belong to report.html, so this file contains no inline style and no script of its own, and it inherits no shell template - the page shell is not this block's to own. Automatic escaping stays on and nothing is ever declared pre-escaped: result data carries assertion text, tracebacks and Selenium messages full of angle brackets and quotes, and the stylesheet handles the wrapping of what remains.
